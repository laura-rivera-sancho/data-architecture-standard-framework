# Security Policy

## Supported version

The latest commit on `main` is the supported portfolio reference.

## Reporting a vulnerability

Do not open a public issue for a suspected security or privacy vulnerability. Use GitHub's private vulnerability-reporting channel when it is enabled, or contact the repository owner privately through the contact method listed on the GitHub profile.

Include the affected component, reproduction conditions, potential impact, and any suggested mitigation. Do not include real credentials, personal data, or confidential information.

## Portfolio security boundaries

- Only synthetic data may be committed.
- Secrets and credentials must remain outside version control.
- Source contracts classify fields even when examples are fictional.
- Consumer-facing models should minimize direct identifiers.
- Future external services must use least-privilege credentials and documented rotation and revocation procedures.
